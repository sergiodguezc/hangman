## Initial findings to investigate in Phase 2

- F01: production has 544 entries but only 40 CEFR annotations (12 A1, 16 A2, 9 B1, 3 B2). Full local classification exists, including 3 C1 and 1 C2 entries; reviewed metadata merge input is empty. `selectNextEntry` throws on empty pools. The UI labels the current word using the pending selection.
- F02: `App` resumes stored credentials on connection without consulting the URL. Credentials are in session storage, not shared local storage. A duplicated/opener tab can inherit them. `GameRoom.finishMatch` can retain a choosing/guessing round when departures finish a match, while the UI renders those controls independently of match status.
- F03: terminal-player notice always says to wait when solved, even when the round/match has ended.
- F04: final positions use array index; sidebar attempts pairwise ties (also incorrect for three tied players). Round scoring has an intentional tiebreaker; equal match totals have no separate winning rule.
- F05: session failures count failed word attempts; board errors count incorrect guesses. Both use an error label. History is not persisted.
- F06: summary uses pending level selection although history already records each completed word's CEFR.

## Phase 2 results

All six issues are addressed locally; no deployment or commit was made.

### F01 — complete CEFR promotion and safe selection

Root cause: only the final 40 targeted rechecks were attached during v1 promotion; the full classification was not merged. Production lexical records exactly match the approved final candidate when `linguistics` is excluded. The repair used existing outputs in order: `cefr-full-544-output.json` → `vocabulary-repair-cefr-recheck-output.json` → `vocabulary-repair-final-cefr-recheck-output.json`. The earlier `industrial` recheck is outside the final 40 and is retained. No API requests or lexical reclassification were performed.

Changed: `data/vocabulary.json`, `data/review/linguistic-metadata.json`, `src/learning/game.ts`, `src/pages/LearningPage.tsx`, `src/learning/i18n.ts`. Coverage is now A1=173, A2=242, B1=104, B2=21, C1=3, C2=1. Metadata and provenance are checked in; runtime does not depend on ignored experiments. All 544 non-linguistic records/IDs/order and all 40 original CEFR values were compared against HEAD and preserved.

Selection now returns `null` for empty pools. The page shows localized recovery instructions without mutating the active round or history. Malformed stored preferences fall back to all. Current-word level comes from its entry; pending next-word preference is shown separately when different.

Verification: real corpus coverage and reviewed-metadata parity in `tests/vocabulary-contract-test.ts`; supported levels, empty pools and preference fallback in `tests/learning-test.ts`; browser starts and advances all four levels and switches levels in an existing session. Passed. Limitation: the advanced pool has only four entries and some classifications have lower confidence. They are preserved estimates from the existing classification, not newly asserted linguistic judgments. The empty-pool return is unit-tested; the empty alert is not exercised in the production-browser suite because all production pools are now populated.

### F02 — invitation precedence and terminal match controls

Reproduced against the pre-fix production build using Firefox 157 WebDriver BiDi:

- Two same-profile tabs sharing local storage but separate session storage: invitation works.
- Independent browser user contexts: invitation works; no shared stored name/session.
- Actual `window.open` from a restored room: new tab inherits a copy of room credentials and silently restores the old room despite a different `sala` URL. This reproduces the audit limitation precisely; ordinary shared local storage alone is not the cause.

Changed: `src/App.tsx`, `src/multiplayer/invitations.ts`, `src/pages/HomePage.tsx`, `src/multiplayer/i18n.ts`; terminal controls also use `src/multiplayer/presentation.ts` and `src/pages/GamePage.tsx`.

Different or invalid invitations now suppress automatic unrelated restoration and stale room snapshots/acks. The invitation displays a localized explanation; existing credentials remain until successful joining, leaving or actual resume rejection. Same-room invitations still resume. Popstate into a conflicting invitation detaches the prior socket without sending an explicit leave. Completed-match phase takes precedence over a retained choosing/guessing round, hiding word-entry and forgiveness controls and active reconnect banners.

Verification: `tests/invitation-test.ts`, `tests/multiplayer-ui-test.tsx`, and `scripts/browser-audit-test.mjs`. Browser checks cover the three isolation modes, reload, same-room restore, joining (credential replacement), invalid invitation (credential preservation), explicit leave and match completion by departure during word choice. Passed. Physical devices, Safari/Chromium and browser Back/Forward races are not separately automated. Existing token lifecycle and live transport tests pass.

### F03 — phase-aware terminal notices

Root cause: `PlayerRoundStatusNotice` considered only the player status. A solved player continued to see “wait for others” after round/match completion.

Changed: `src/multiplayer/presentation.ts`, `src/components/PlayerRoundStatusNotice.tsx`, `src/pages/GamePage.tsx`. The phase is derived from authoritative match/round status. Personal terminal notices and forgiveness waiting/actions render only during guessing; completed-round and completed-match results take precedence. Guess submission also requires the derived guessing phase.

Verification: `tests/multiplayer-ui-test.tsx` drives actual `GameRoom` transitions with two and three participants: before guessing, one solver while another continues, everyone finished, last round, rematch readiness and new match. Static rendering verifies notice absence/presence for those states. Existing N-player/forgiveness/match suites pass. Full multi-browser rematches are not automated by the optional browser suite.

### F04 — shared total-score ranks

Root cause: final results used index+1; sidebar used a pairwise tie shortcut that also failed for three tied players. Server roster order is stable ordering, not a total-score winning tiebreaker. Round scoring has its own intentional error/time/roster ordering and remains unchanged.

Changed: `shared/ranking.ts`, generated `dist-server/shared/ranking.js`, `src/components/Scoreboard.tsx`, `src/pages/GamePage.tsx`. Both presentations use competition ranking: 1,1,3; ties of any size share a place. Final score values use the server's result snapshot.

Verification: `tests/multiplayer-ui-test.tsx` checks helper and rendered sidebar/final results for 1–1, 5–5–5–3–3–1 and unsorted 3–1–2–2, including reversed input order for ties. Passed. Existing population distinction is preserved: sidebar ranks active players; final results include the historical roster, so positions can differ after departures. No scoring rules changed.

### F05 — distinguish letters from word attempts

Root cause: board errors count incorrect letter guesses, whereas session failures count failed word attempts. Both were labelled errors. Learning history is in memory, so there is no persisted statistics format to migrate.

Changed: `src/learning/i18n.ts` (both languages). Board errors are “Lletres incorrectes” / “Letras incorrectas”; summaries/session lines distinguish words solved and not solved, and label the success percentage. Calculations and history shape are unchanged.

Verification: `tests/learning-test.ts` covers a successful word with two wrong guesses, a failed word at six errors, per-word failure totals, 50% success, and both localized summaries/stat lines. Browser mixed-session summary also checks the clarified label. Passed.

### F06 — summaries describe completed practice

Root cause: summary read the mutable selected level, ignoring the CEFR already recorded with completed attempts.

Changed: `src/learning/game.ts`, `src/pages/LearningPage.tsx`, `src/learning/i18n.ts`. `practicedLearningLevels` derives an ordered unique set from history; summary lists those level groups. Selecting or starting an unfinished advanced word does not add it to completed practice. Empty history retains the empty-summary message.

Verification: `tests/learning-test.ts` checks mixed basic/intermediate history and both languages; browser completes basic/intermediate words, selects advanced without playing it, and verifies that only basic/intermediate appear in the summary. Passed.

## Setup and follow-up

No confirmed F01–F06 defect remains open in the tested scope. Prioritized follow-up:

1. Editorial: review/expand the four-word advanced pool, keeping CEFR provenance and daily IDs stable. Existing CEFR estimates are not an official certification; do not silently relabel to increase coverage.
2. Verification: add Chromium/WebKit and physical mobile smoke coverage, same-document Back/Forward invitation races, and browser-level multi-player rematches/reconnect timeout scenarios. Current domain/transport coverage remains in place.
3. Pipeline: promote future approved vocabulary/metadata atomically from one reviewed artifact; old pipeline inputs can otherwise overwrite approved lexical repairs. Coverage/parity checks now catch missing annotations.
4. Optional architecture/performance: lazy-load learning/daily vocabulary, consolidate route metadata, and extract App's session coordination incrementally when next changed. Multi-instance persistence is a separate project; continue using one server process.

Known existing limitations outside these fixes: daily challenge rolls over on remount rather than a guaranteed midnight refresh; server rooms disappear on process restart; final historical rankings and active-member sidebar have different populations after departure; a one-player finished room can request rematch but cannot start one without a second eligible member. No broad state or UI redesign was attempted.
